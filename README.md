# home-ssh-toolbox

Набор интерактивных утилит для управления SSH-доступом в домашней сети — на Linux (в том числе РЕД ОС) и Windows.

## Зачем это нужно

Если у вас дома несколько хостов (сервер, NAS, Raspberry Pi, Windows-машина, Mac mini), рано или поздно появляется рутина:

- раскладывать SSH-ключ по всем хостам, чтобы не вводить пароль;
- вести единый список хостов сети;
- поддерживать в актуальном состоянии `/etc/hosts`;
- чистить `~/.ssh/known_hosts` от мёртвых записей;
- отзывать ключ, если он больше не нужен.

Эти скрипты автоматизируют всё это в интерактивном меню, с цветным выводом, реестром операций и безопасными операциями (всегда с бэкапом).

## Что умеют скрипты

### Общие возможности (Linux и Windows)

- 📋 **Инвентарь хостов** — единый список `~/.ssh/home_hosts.txt` со всеми хостами сети
- 🔑 **Управление SSH-ключами** — выбор существующего, генерация нового (ed25519 / RSA 4096), аудит
- 📡 **Рассылка ключа по хостам** — через `ssh-copy-id` или его аналог, с проверкой, работает ли ключ уже
- 📊 **Реестр операций** — `~/.ssh/deploy_keys.log`, где видно, куда и под каким пользователем разложен ключ
- 🧹 **Очистка `known_hosts`** — удаление записей о хостах, которые больше не отвечают
- 🗑️ **Удаление конкретного хоста из `known_hosts`** — через `ssh-keygen -R`
- 🎨 **Цветной интерфейс** — меню, статусы, отчёты

### Только Linux

- 🔄 **Синхронизация `/etc/hosts` с инвентарём** — добавление недостающих записей с `sudo`
- 📥 **Импорт `/etc/hosts` с удалённого хоста** — прочитать файл по SSH и добавить недостающие записи в свой
- 👁 **Просмотр `/etc/hosts` удалённого хоста** — без импорта, просто посмотреть
- 🔍 **Обнаружение хостов**:
  - через DNS AXFR (если ваш DNS-сервер разрешает зонный трансфер);
  - локальным `nmap`;
  - через mDNS (Avahi/Bonjour) — находит macOS и Linux с Avahi;
  - через удалённый хост по SSH (`nmap` или ARP-таблица на том хосте).

## Требования

### Linux / РЕД ОС

- `bash` 4+
- `openssh-clients` (`ssh`, `ssh-keygen`, `ssh-copy-id`, `ssh-keyscan`)
- `sudo` — для модификации `/etc/hosts`
- Опционально:
  - `bind-utils` — для `dig` (AXFR)
  - `nmap` — для сканирования сети
  - `avahi-tools` — для mDNS

Установка на РЕД ОС:

```bash
sudo dnf install -y openssh-clients bind-utils nmap avahi-tools
sudo systemctl enable --now avahi-daemon
```

### Windows

- Windows 10/11
- OpenSSH Client (встроен, или установить через «Параметры → Приложения → Дополнительные компоненты»)
- PowerShell 5.1+ (встроен)

## Установка

```bash
git clone https://github.com/ArsIS-02/home-ssh-toolbox.git
cd home-ssh-toolbox
```

### Linux

```bash
chmod +x linux/ssh-home-toolbox.sh
./linux/ssh-home-toolbox.sh
```

### Windows

Скопируйте `windows/ssh-toolbox.cmd` в удобное место и запустите двойным кликом. Если PowerShell блокирует выполнение — скрипт это обходит через `-ExecutionPolicy Bypass`.

**Важно:** файл должен быть сохранён в UTF-8 без BOM. Если при первом запуске увидели кракозябры — откройте файл в VS Code, в правом нижнем углу кликните на `UTF-8 with BOM` → «Save with Encoding» → `UTF-8`.

## Использование

### Linux — главное меню

```
╔══════════════════════════════════════════╗
║  Домашняя SSH-инфраструктура             ║
╚══════════════════════════════════════════╝
  Ключ:      /home/user/.ssh/id_ed25519.pub
  Инвентарь: /home/user/.ssh/home_hosts.txt (5 хостов)
──────────────────────────────────────────

  1) Инвентарь хостов
  2) Синхронизация /etc/hosts
  3) Разослать ключ по хостам (инвентарь)
  4) Разослать ключ по хостам (/etc/hosts)
  5) Ввести хост вручную
  6) Управление SSH-ключом
  7) Очистить known_hosts
  8) Удалить конкретный хост из known_hosts
  9) Показать реестр
  10) Показать итоги
  0) Выход
```

### Windows — главное меню

```
==========================================
  Интерактивная рассылка SSH-ключа (Win)
==========================================
  Ключ:   C:\Users\user\.ssh\id_ed25519.pub
  Реестр: C:\Users\user\.ssh\deploy_keys.log
------------------------------------------

  2) Ввести хост вручную
  3) Управление SSH-ключом
  4) Очистить known_hosts (все мёртвые хосты)
  5) Удалить конкретный хост из known_hosts
  6) Отозвать ключ с хостов
  7) Показать реестр
  8) Показать итоги
  0) Выход
```

### Типичный сценарий первого запуска

1. **Сгенерировать или выбрать ключ** — `Управление SSH-ключом → Сгенерировать новый`. Рекомендуется `ed25519`.
2. **Наполнить инвентарь**:
   - Linux: `Инвентарь хостов → Импортировать из /etc/hosts`, затем `Обнаружить через удалённый хост` для полноты;
   - Windows: список хостов берётся прямо из `C:\Windows\System32\drivers\etc\hosts`.
3. **Синхронизировать `/etc/hosts`** (Linux) — добавить недостающие записи.
4. **Разослать ключ** — `Разослать ключ по хостам`, выбрать все или по одному.

## Формат инвентаря (Linux)

`~/.ssh/home_hosts.txt` — обычный текстовый файл, формат как в `/etc/hosts`:

```
192.168.1.10  macmini.local  macmini
192.168.1.11  nas.local      nas
192.168.1.15  redos.local    redos
```

Строки, начинающиеся с `#`, игнорируются.

## Реестр операций

Все успешные операции пишутся в `~/.ssh/deploy_keys.log`:

```
host user added 2026-09-15 14:30:00 fp=SHA256:xxxxx...
```

Хранит имя хоста, пользователя, дату и отпечаток ключа. Используется для проверки, работает ли ключ уже, и для отзыва ключа с хостов.

Сбросить реестр: `rm ~/.ssh/deploy_keys.log`

## Безопасность

- Все изменения — только с подтверждением.
- Удаление записей из `known_hosts` и модификация `/etc/hosts` — с бэкапом.
- Отзыв ключа с хостов выполняется по **отпечатку**, а не по комментарию.
- Пароли не сохраняются: `ssh-copy-id` и его аналоги спрашивают их в интерактивном режиме.
- Скрипт ничего не делает на удалённых хостах, кроме явно запрошенного действия.

**Важно:** скрипт не заменяет проверку ключа хоста. Первое подключение к новому хосту делается с `StrictHostKeyChecking=no`, потому что `ssh-copy-id` должен как-то аутентифицироваться. Если для вас это критично — подключайтесь к хосту вручную заранее, чтобы ключ попал в `known_hosts`, а потом запускайте скрипт.

## Ограничения

- **Linux-версия** рассчитана на bash 4+, использует GNU-утилиты. Проверялась на РЕД ОС.
- **Windows-версия** использует PowerShell 5.1. Работает и на PowerShell 7, но не тестировалась специально.
- **Первый вход по паролю обязателен** — если ключа на хосте ещё нет, `ssh-copy-id` (или его аналог) должен как-то авторизоваться.
- **Хешированные записи `known_hosts`** не разбираются и не удаляются — они остаются как есть.
